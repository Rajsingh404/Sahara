# SAHARA paper: what is still missing

The paper is now in the conference's Springer SVProc format (`sahara.tex`, `sahara.pdf`, 13 pages, single column).
The earlier IEEE two-column version is kept as `sahara_ieee.tex` / `sahara_ieee.pdf` in case you submit elsewhere.
`sahara_source.zip` holds everything the conference asks for (`.tex`, `svproc.cls`, figures).

Every red **TBD** in `sahara.pdf` is a number nobody has measured yet. Don't submit while any are left.
Every number already in the paper comes from the repo (`docs/dataset_card.md`, `data/metadata/class_thresholds.json`,
the manifests, the app and firmware branches) or from the team-recording metadata. The latency and false-alarm
bounds in Section IV-C are analytical, and the paper says so.

## Results to run (on your Mac, after the full retrain)

| Paper location | What to run | What to paste |
|---|---|---|
| Table V, row 1 | Window-level retrain (1 s windows, not clip means), then `threshold_search.py` on val, then evaluate **test** at the calibrated thresholds | mAP, macro recall, recall averaged over smoke_alarm/siren/glass_break |
| Table V, rows 2-4 | Mix the **test** targets with held-out iNoise/DESED chunks at a fixed 10, 0 and −5 dB (`synthetic_mixing.py` with a fixed SNR) and evaluate | same three columns |

| Table V, row 6 | `false_alarm_eval.py`, run as a **stream** (1 s windows, 0.5 s hop, the app's 1-of-3/2-of-3 + 10 s cooldown rule) over the DESED + iNoise test audio | false alarms per hour |
| Table VI | Five runs: unweighted BCE @0.5 no smoothing → + weighted BCE → + calibration → + 2-of-3 for all → + asymmetric rule | mAP, safety recall, FA/h for each |
| Table VII | `to_tflite.py`, `quantize.py`, `validate_tflite.py`; the app on a real phone; the band on hardware | sizes, INT8 mAP change, ms per window, onset→alert seconds, alert→buzz ms, %/h battery, band mA and hours |
| Abstract last sentence, Section VII-C paragraph | Write from Tables V and VI | 1 sentence + 2-3 sentences |

Keep the run folder (config, git hash, metrics JSON) for every number. Reviewers and your guide may ask for it.

## Before submitting

1. Check the venue's page limit and whether review is double-blind. If it is, remove the names and the NMIMS line.
   Springer's template asks for an abstract of 70-150 words; ours is 141 without the TBD sentence, so keep that sentence short (about 10 words) or trim elsewhere.
2. Recompile: `pdflatex sahara.tex` twice (needs `svproc.cls`, `aliascnt.sty`, `remreset.sty` and `figures/` in the same folder). Figures are regenerated by `python make_figures.py`.
3. If the new results change the story (for example, siren improves a lot), update the sentences in Section VII-A
   and the conclusion so they stay true.
4. Don't quote 0.618 or 0.783 anywhere. 0.783 came from a ~25-clip AudioSet-only test, and 0.618 isn't in the repo.
   The paper uses the 698-clip baseline (mAP 0.651).
